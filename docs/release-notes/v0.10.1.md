## Security

- **Updated the Web UI's development dependency `vitest` from 3.2.7 to 4.1.11**, which resolves the moderate advisory GHSA-82fw-gwwq-j7x9 in `vitest` and `@vitest/mocker` (affected versions up to 4.1.10). `npm audit` in `packages/web`, development dependencies included, no longer reports it. `vitest` is only used to run the Web UI's tests: it is not part of the `graph-engine` binary or the Web UI embedded in it, so no shipped code changes. The existing test suite runs unchanged on vitest 4.

## Fixes

- **Every Go test that uses MySQL now refuses the working database.** The check that stops the MySQL tests from running when `GRAPH_TEST_MYSQL_DATABASE` is empty or names the working database `graph_ops` (compared case-insensitively) used to cover only `internal/store`'s own tests. The claim-concurrency test in `internal/store` and the MySQL backend of `cmd/graph-engine`'s delete-ticket / update-ticket tests read the same variables without it, so pointing them at the working database made them write rows there. The check and the reading of the `GRAPH_TEST_MYSQL_*` variables now live in one test-only package, `internal/mysqltestenv`, which all three use; it is tested on its own and is not linked into `graph-engine`.

## Behavior changes

- For contributors running the Go tests by hand: setting `GRAPH_TEST_MYSQL_HOST` without `GRAPH_TEST_MYSQL_DATABASE`, or with `GRAPH_TEST_MYSQL_DATABASE=graph_ops`, now fails the claim-concurrency test and the MySQL subtests of the delete-ticket / update-ticket CLI tests before they connect, as it already did for the rest of the MySQL tests. Use a throwaway database; `dev/mysql/test.sh` creates one per run and CI sets `graph_ops_ci`, so neither is affected. `GRAPH_TEST_MYSQL_PORT` must now be a number between 1 and 65535 in every MySQL test.

## Upgrade notes

- Nothing is required. This release changes no runtime behaviour, configuration or data; the changes above only affect development and testing.
