## Changes

- **"Select all" in the ticket-list filters.** Each of the four filters of the Web UI's ticket list (status, assignee, priority, label) now has a "Select all" button next to "Clear selection" at the bottom of its panel. It checks every option of that filter in the order the panel lists them, including the assignee filter's "Unassigned", keeps any selected value that is no longer offered as an option (such as an assignee who disappeared on a refresh), and leaves the panel open, so you can uncheck the few options you do not want -- for example, show every status except Done and Closed. The button is disabled when every option is already checked or the filter has no options; focus stays in the panel when it becomes disabled, so Escape still closes the panel.
  - With every option checked, the filter still reads "n selected", not "All". Checking everything is not always the same as no filtering: the label filter matches tickets that have any of the selected labels, so it hides tickets that have no label at all, and an assignee who appears on a later refresh is not included. For status, priority and assignee, checking every option shows the same tickets as selecting none.
- **Screen readers hear what "Select all" and "Clear selection" did.** In each of the ticket-list filters, pressing "Select all" now announces "All options selected (n)" and pressing "Clear selection" announces "Selection cleared" (in Japanese: "n 件すべてを選択しました" / "選択を解除しました") through a polite live region. Before, only the control that received focus was read out -- the first checkbox or the filter button -- so it was not clear that the whole selection had changed. n is the number of options in the panel (DFLT-00267).
- **For contributors: a new worktree without `npm ci` fails fast.** In a checkout where dependencies are not installed (typically a fresh git worktree), `npm run lint`, `npm test` and `npm run build` in `packages/web` now stop at once with a message telling you to run `npm ci` in the checkout's root, instead of picking up the parent repository's tools and failing with `ERR_MODULE_NOT_FOUND` for `@eslint/js` (or hanging in vitest). The README's Troubleshooting section describes it (DFLT-00267).

## Fixes

- **The ticket list page reads and works better with very large text.** Five leftovers of the v0.10.0 reflow fixes (DFLT-00251) are fixed. (1) In English on a 320-336px screen with the page's text at 200%, the note "(Click to expand and view the graph and each node's artifacts)" in the summary above the list ran past the summary card; the heading now moves the note under the title and breaks it inside a word when the card is narrower than 12rem, following the text size however it is set. (2) At 1024px and wider with 200% text the header, pinned to the top of the window, grew to about 530px and covered the buttons of the ticket header rows as they scrolled under it (WCAG 2.4.11); the header is now pinned only while it takes at most a quarter of the window's height or is at most 128px tall (as it is at the default text size), and otherwise scrolls away with the page as it does on narrower screens. (3) In a 160px-wide window (a 320px screen at 200% zoom) with a three-digit page number ("100 / 123"), the page-navigation buttons ended 9px past their row; they now sit closer together there. (4) The labels under the summary's numbers ("Total Tickets", "In Progress", "In Review", "Done", "Node Progress") grow with the browser's text size (still 11px at the default size). (5) The summary's node progress breaks only after the slash, never inside a number, up to five digits ("99997/" / "99999"). At the default text size, 320px and wider, the page looks exactly as before, and the header is pinned from `lg` up as before, however low the window (DFLT-00258).
- **Autopilot child sessions open in a Terminal.app tab more reliably.** When the autopilot opens a child session as a new tab of the orchestrator's Terminal.app window, it now waits 0.2 seconds after seeing the window in front before sending Cmd+T (it used to send it right away), and waits up to about 6 seconds for the new tab, checking every 0.2 seconds (it used to give up after about 3 seconds and open a new window instead). To make room for the longer wait, the time limit on `osascript` goes from 10 to 15 seconds and the wait for the tab lock from 15 to 20 seconds, so a launch can now take about 45 seconds at worst instead of about 35 (DFLT-00269).
- **Node rows in a ticket's node list keep their badges apart, stay inside the card in a very narrow window, and grow with the browser's text size.** Leftovers of the v0.10.0 node-row fixes (DFLT-00253) are fixed. (1) At 1280px and wider, in a row whose node name is shortened with an ellipsis, the last badge (usually the artifact count) touched the status badge with no space between them; there is now always at least 4px (0.25rem) between them. A row with that much room to spare looks exactly as before; a row that had less than 4px to spare shortens its name by up to 4px more. (2) In a 160px-wide window (a 320px screen at 200% zoom), the retry, manual and artifact-count badges ran 3-26px past the node card, and in English the status badge ran up to 29px past it; these badges now wrap onto more lines below 1280px (80rem) instead, and stay on one line at 1280px and wider. (3) The node-type, status, retry, manual and artifact-count badges now grow with the browser's default text size (they were fixed at 10-11px, WCAG 1.4.4); at the default 16px they are exactly the same size as before. With 200% text on a 320-336px screen they stay inside the card. For contributors: the rem media-query prefixes `[@media_not_all_and_(min-width:80rem)]:` and `[@media(max-width:15rem)]:` are now the named Tailwind variants `below-80rem:` and `upto-15rem:` (in `packages/web/tailwind.config.js`), with the same media conditions. When both set the same property on an element the narrower `upto-15rem:` wins, while core screen variants such as `max-sm:` still win over both; the comment next to their definition explains the order (DFLT-00260).
