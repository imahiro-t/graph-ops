## Changes

- **"Select all" in the ticket-list filters.** Each of the four filters of the Web UI's ticket list (status, assignee, priority, label) now has a "Select all" button next to "Clear selection" at the bottom of its panel. It checks every option of that filter in the order the panel lists them, including the assignee filter's "Unassigned", keeps any selected value that is no longer offered as an option (such as an assignee who disappeared on a refresh), and leaves the panel open, so you can uncheck the few options you do not want -- for example, show every status except Done and Closed. The button is disabled when every option is already checked or the filter has no options; focus stays in the panel when it becomes disabled, so Escape still closes the panel.
  - With every option checked, the filter still reads "n selected", not "All". Checking everything is not always the same as no filtering: the label filter matches tickets that have any of the selected labels, so it hides tickets that have no label at all, and an assignee who appears on a later refresh is not included. For status, priority and assignee, checking every option shows the same tickets as selecting none.

## Fixes

- **The ticket list page reads and works better with very large text.** Five leftovers of the v0.10.0 reflow fixes (DFLT-00251) are fixed. (1) In English on a 320-336px screen with the page's text at 200%, the note "(Click to expand and view the graph and each node's artifacts)" in the summary above the list ran past the summary card; the heading now moves the note under the title and breaks it inside a word when the card is narrower than 12rem, following the text size however it is set. (2) At 1024px and wider with 200% text the header, pinned to the top of the window, grew to about 530px and covered the buttons of the ticket header rows as they scrolled under it (WCAG 2.4.11); the header is now pinned only while it takes at most a quarter of the window's height or is at most 128px tall (as it is at the default text size), and otherwise scrolls away with the page as it does on narrower screens. (3) In a 160px-wide window (a 320px screen at 200% zoom) with a three-digit page number ("100 / 123"), the page-navigation buttons ended 9px past their row; they now sit closer together there. (4) The labels under the summary's numbers ("Total Tickets", "In Progress", "In Review", "Done", "Node Progress") grow with the browser's text size (still 11px at the default size). (5) The summary's node progress breaks only after the slash, never inside a number, up to five digits ("99997/" / "99999"). At the default text size, 320px and wider, the page looks exactly as before, and the header is pinned from `lg` up as before, however low the window (DFLT-00258).
