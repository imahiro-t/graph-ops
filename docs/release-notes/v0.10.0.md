## Fixes

- **Saving `config.json` no longer drops the top-level keys this version does not know.** `graph-engine` -- the CLI and the UI server alike -- rewrites `$HOME/.graph-ops/config.json` whenever it saves: switching projects (`use-project`, or in the Web UI), creating a project with a local path, deleting a project, and saving App Settings. It used to write back only the settings its own version knew, so a binary of another version silently deleted the rest. That is how a v0.9.0 UI server that was still running after an update removed the new `autopilotSettings` the moment someone switched projects. Every save now keeps each top-level key it does not know, with its value written back exactly as it was read: nested objects, arrays, integers beyond 2^53, `1.0`, `null`, and escaped forms such as `\u003c` are not re-encoded (only whitespace and indentation are normalized). Unknown keys are written after the known ones, in key-name order. A key that differs from a known key only in case (for example `DBBackend`) is still treated as that known key and written back once, under its correct spelling. When there is no unknown key, the file is written byte for byte as before. Only the top level is preserved; to keep that enough, the settings in the file stay flat or inside plain JSON maps, and a test now fails if a setting whose value could drop nested keys is added.

## Documentation

- The README (English and Japanese) explains, under "Updating to a new release", that a UI server from 0.9.0 or earlier that is still running after the update drops settings it does not know, such as `autopilotSettings`, whenever it saves `config.json`, and why that means restarting it right away.

## Upgrade notes

- **Restart the UI server right after updating, before you change any autopilot setting.** A UI server from 0.9.0 or earlier does not have the fix above. If one is still running after you update to 0.10.0 and you save 0.10.0 settings such as `autopilotSettings`, they disappear the next time that old server writes `config.json` -- for example when you switch projects in its Web UI. Stop the old server and start the new one as described in "Updating to a new release" in the README. Settings that have already disappeared cannot be recovered; set them again after the restart.
