## Security

- **Removed `GET /api/tickets/{id}/executable-nodes`.** This endpoint changed state -- it seeded a ticket's graph and moved nodes to IN PROGRESS / IN REVIEW -- yet it was a `GET`, and `GET` is exempt from the CSRF header check every state-changing method has to pass. That made it drivable from any web page the user happened to open, with nothing more than `<img src="http://127.0.0.1:49173/api/tickets/PFX-00001/executable-nodes">`; ticket IDs are sequential, so guessing one is not a barrier. The endpoint was undocumented and unused: the Web UI never called it, and the CLI's `get-executable-nodes` calls the engine directly and is unaffected.

- **Removed the `/artifacts-static/` route.** It served the artifacts directory (`~/.graph-ops/artifacts` by default) straight off the filesystem, on the app's own origin, with no sandbox and with directory listings enabled. Agent-authored HTML opened from there ran as same-origin script, which meant it could call this unauthenticated API -- including `POST /api/claude/launch` -- with the CSRF header attached. `GET /api/artifacts/{id}/content`, which serves artifacts with `Content-Security-Policy: sandbox allow-scripts` and `X-Content-Type-Options: nosniff`, is unaffected and remains the way the UI reads artifact content. The unused Vite dev-server proxy for the removed route is gone too.

- **Every response now carries `X-Frame-Options: DENY` and `Content-Security-Policy: frame-ancestors 'none'`.** Without them, any site could embed the UI in an `<iframe>` and click-jack a user through a one-click action -- passing a review approval gate, or launching Claude Code in an external terminal. The existing defenses do not cover this: an embedded frame loads the real app on its real origin, so the Host check passes and the app attaches the CSRF header itself. The one exception is `GET /api/artifacts/{id}/content`, which keeps its sandbox and uses `frame-ancestors 'self'` so the UI's own artifact preview keeps working.

- **The Web UI sends a Content-Security-Policy of its own**, and a remote image inside a markdown artifact is no longer fetched just because the artifact was rendered: it shows the source's host and loads only after the reader clicks.

- **The API server sets `ReadHeaderTimeout` and caps request bodies at 64 MiB.** Both matter when the server is deliberately exposed with `--host 0.0.0.0`, where a Slowloris-style client or an unbounded request body would otherwise tie up goroutines or memory. A body over the cap is answered `413` with `REQUEST_BODY_TOO_LARGE`, never a `5xx`.

## Fixes

- **`PATCH /api/tickets/{id}` and `PATCH /api/nodes/{id}` validate their input.** A ticket's `status` and a node's `status` now have to be values the engine understands, a ticket's `title` cannot be set to an empty string, and a node's `max_iterations` has to be 1 or greater. A rejected request changes nothing at all. Setting a ticket to `CLOSED` through `PATCH` is refused as well: use `POST /api/tickets/{id}/close`, which records the reason alongside it.

- **`PATCH /api/nodes/{id}` keeps the ticket's status in step with its nodes.** It was the one path that changed a node without re-deriving the owning ticket's status, so (for example) a PATCH that moved the last node to DONE left the ticket at IN PROGRESS indefinitely. A CLOSED ticket is still never resurrected, and its `closed_reason` is left untouched.

- **`PATCH /api/nodes/{id}` no longer accepts `name`, `type` or `iteration_count`**, and answers `400` if one is sent. A node's name and type come from the workflow catalog its graph was expanded from, and `iteration_count` is the engine's own bookkeeping as review gates loop. No caller in this repository set any of them.

- **An unknown `/api/` path returns a JSON `404`** (`API_ROUTE_NOT_FOUND`) instead of falling through to the SPA and answering `200` with `index.html`.

## Upgrade notes

- The two removed routes were undocumented and had no callers in this project. If you built something that polled `GET /api/tickets/{id}/executable-nodes` to drive a graph, use the CLI's `graph-engine get-executable-nodes` instead; if something read files from `/artifacts-static/`, use `GET /api/artifacts/{id}/content`.
- The narrowed `PATCH /api/nodes/{id}` is a compatibility change for any external caller that set `name`, `type` or `iteration_count`. Nothing in this repository did.
