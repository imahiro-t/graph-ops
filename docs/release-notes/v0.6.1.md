## Security

- **The v0.6.0 binaries were built with Go 1.25.0 and shipped with known, reachable standard library vulnerabilities. Update to v0.6.1.** Running `govulncheck -mode=binary` against the published v0.6.0 assets reported 27 vulnerabilities reachable from graph-engine's own code paths -- not merely present in the binary. They affect code this project actually runs: the Web UI server (`net/http`), the TLS connections to MySQL and to an HTTP data source (`crypto/tls`, `crypto/x509`), and URL parsing (`net/url`). v0.6.1 contains no functional change for this; it is the same code rebuilt with a patched Go toolchain.

- **The cause: the Go toolchain was never pinned.** CI and the release workflow both take their Go version from `packages/core-go/go.mod` via `actions/setup-go`'s `go-version-file`. With only a `go 1.25.0` line and no `toolchain` line, that is the version the release binaries were built with, and it never moved to a patch release. Both `packages/core-go/go.mod` and `examples/jira-datasource/go.mod` now carry `toolchain go1.25.14`, so CI, release builds and local builds all use the same patched toolchain. The version is still recorded in exactly one place per module, and `go-version-file` is unchanged.

- **The release workflow now refuses to publish a vulnerable binary.** A new `vulncheck` job runs after the binaries are built and before the Release is created. For each of the 4 binaries it checks that `go version <binary>` reports at least the Go version pinned in the `toolchain` line, and that `govulncheck -mode=binary <binary>` finds nothing reachable. It also fails if it does not find exactly 4 binaries, so a scan that silently matches no files cannot pass as a green job. `govulncheck` is installed at a pinned version and runs in its own job, so the job that produces the published binaries gains no additional third-party build code.

- **Updated the indirect dependency `filippo.io/edwards25519` from v1.1.0 to v1.1.1** (pulled in by `github.com/go-sql-driver/mysql`), which carried GO-2026-4503. That one was not reachable from graph-engine's code; it is updated here because this release rebuilds and republishes every binary anyway.

## Upgrade notes

- **Update to v0.6.1.** Update from the `/plugin` menu, or run `claude plugin update graph-ops@graph-ops` in a terminal. The first run after the update downloads the matching `graph-engine` binary. There is no need to uninstall or reinstall.
- Nothing else is required. This release changes no behaviour, no configuration and no data: there is no migration, and existing SQLite, MySQL and HTTP data sources keep working as they did in v0.6.0.
- To confirm what you are running: `go version <path to the graph-engine binary>` prints the Go version it was built with. For v0.6.1 assets this is `go1.25.14` or newer; for v0.6.0 it was `go1.25.0`.
- Building from source now requires Go 1.25.14 or a toolchain that is allowed to fetch it (the default `GOTOOLCHAIN=auto` does this automatically). With `GOTOOLCHAIN=local` and an older local Go, the build fails instead of silently using it.
