## Changes

- **Each Claude Code session shows its ticket and what it is doing above the prompt.** When several terminals run `process-ticket` or an autopilot at once, it was hard to tell which terminal worked on which ticket, and an AskUserQuestion could be answered in the wrong one. The plugin now ships a Claude Code mod (`hooks/hooks.json`, `hooks/register.tsx`) that draws a status band above the prompt: the ticket's ID and title and the session's current work (refining, running with the running nodes' names and types, awaiting approval, waiting for your answer, releasing, finishing). An AskUserQuestion dialog gets a one-line heading with the same ticket. An autopilot orchestrator also shows the tree's progress (done / in progress / remaining, plus blocked / failed), the ticket whose child session is working now, and the latest result (`done` / `blocked` / `failed`). It is on as soon as the plugin is installed or updated; the band appears in the language set by `/graph-ops:onboarding` (English or Japanese). The status is kept per Claude Code session in `$HOME/.graph-ops/session-status/<session ID>.json`, keyed by `CLAUDE_CODE_SESSION_ID`, so terminals never show each other's tickets and a session that runs no GraphOps skill shows nothing; sessions started from the Web UI and skills run by hand work the same way. `refine-ticket`, `begin-session`, `get-executable`, `wait-node` and the `graph-engine autopilot` commands write it as a side effect, the skills add the moments the engine cannot see, and the commands subagents run (`get-ticket`, `add-artifact`, `complete-node`) never write it. Titles, node names and other text are stripped of control characters and terminal escape sequences, both when written and before drawing. A session's file is removed when its skill ends, and files nobody has written for 7 days are cleaned up automatically -- so a session left awaiting approval for more than 7 days without any graph-engine call can lose its band until its next call. README ("Status band above the prompt") and docs/autopilot.md describe it (DFLT-00383).
- **New `graph-engine session-status set|clear|show` command.** `set [--ticket <ticketId>] --phase <phase> [--detail <text>] [--role worker|controller]` records the current session's status (the ticket's title is read from the database), `clear` removes it, and `show` prints it -- use `show` first when the band does not appear. Without `CLAUDE_CODE_SESSION_ID` every subcommand does nothing and exits 0. Writing is best effort everywhere: a failure prints one warning line on stderr and never changes a command's output or exit code (DFLT-00383).
- **Not verified yet for the status band**: how it looks in a real interactive terminal (including whether the band above the prompt stays while an AskUserQuestion dialog is open; the dialog's heading covers that case either way), whether a Claude Code too old to support mods still loads the plugin's skills, agents and commands without errors, whether a plugin installed from the marketplace loads the mod without an extra approval, and Windows (the mod looks under `HOME`, then `USERPROFILE`). It was tested with the mod's automated tests and by loading the plugin with `claude --plugin-dir` on Claude Code 2.1.312-2.1.316 (DFLT-00383).
- **The `graph-engine` binaries are built with Go 1.26.10.** The toolchain pin moves from Go 1.26.9, whose `crypto/x509` is affected by GO-2026-6809 (distrust of compromised intermediate certificates, reachable through `x509.Certificate.Verify`), fixed in Go 1.26.10. Building GraphOps from source now needs Go 1.26.10; with the default `GOTOOLCHAIN=auto`, `go` downloads it automatically.
