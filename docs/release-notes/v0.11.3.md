## Changes

- **Autopilot child sessions open as Terminal.app tabs instead of falling back to new windows when the screen is unlocked.** Looking into the run files and macOS's unified log showed that the tab fallbacks with the screen unlocked were almost all a synthesized Cmd+T that never reached Terminal: Terminal and the orchestrator's window stayed in front, yet no new tab appeared anywhere (9102). The earlier fixes (DFLT-00154, DFLT-00183, DFLT-00361, DFLT-00362) had all changed what happens after Cmd+T, so none of them could help with that. The tab script now opens the tab by pressing Terminal's New Tab menu item over Accessibility (found by its Cmd+T shortcut, not its title, and only when exactly one such item sits next to the Cmd+N item), and sends Cmd+T only when no such item is found. It also checks again, right before opening the tab, that Terminal and its window are still in front, and brings them back (at most twice) when they are not. When no tab has appeared about 2 seconds after the first attempt, it tries once more by Cmd+T, after reading the tabs again so that a first tab that is merely late is taken instead of a second one being opened. A tab that opened only at the retry is counted in the run file's `terminal_retried_tabs`; a second new tab that appears after the retry (most likely the first attempt's, appearing late) is logged as `stray_tab`, counted in `terminal_stray_tabs`, and the session still runs in the tab taken. `terminal_late_tabs` and `late_tab` now also cover a first attempt's tab taken right before the retry. Every failure records more for the next investigation: `open_method` (`menu`, `menu-failed`, `keystroke-no-menu`, `keystroke-retry`), `retried`, `retry_frontmost_app`, `refocused`, `front_window_id_before`, `secure_input` (who holds secure keyboard entry) and `hid_idle_ms` (time since your last input), and two new phases, `menu-pressing` and `menu-pressed`. The `osascript` limit is now 30 seconds (from 20), the wait for the tab lock 35 seconds (from 25), and a launch's worst case about 81 seconds (from about 59). While the screen is locked, sessions still open in new windows (a macOS restriction; that was 83% of the fallbacks looked into). docs/autopilot.md describes how the tab is opened, the investigation, and the remaining trade-off (a late first tab and the retry's tab seen in the same read is still a 9104) (DFLT-00377).
- **The run file now also tells how the tabs that did open were opened.** Until now `open_method` was kept only for a tab that could not be opened, so a Mac where the New Tab menu item is never found -- every launch silently falling back to Cmd+T -- looked no different in the run file as long as the tabs opened. Each launch whose tab opened is now counted in the local run file's `terminal_tab_open_methods`, by method (`menu`, `menu-failed`, `keystroke-no-menu`, `keystroke-retry`, or `unknown` for a method not logged or not known), and, unless it was `menu`, in `terminal_non_menu_tabs` as well, next to `terminal_late_tabs`, `terminal_retried_tabs` and `terminal_stray_tabs`; like those, both are cleared on a takeover or an adoption and left out of the copy shared with other members. A failure's `open_method` and the existing counts are unchanged. docs/autopilot.md describes how to read the new counts (DFLT-00378).
- **A stray Terminal tab that appears after the tab script's 1-second look is now found and recorded.** When a session's tab opened only at the retry, the first attempt's tab could still appear after the script had stopped looking for it (1 second, so that launches do not wait longer), and then stayed empty with nothing in the run file or on stderr. Such a launch is now looked at again later: the next `autopilot wait` poll or `autopilot launch` that comes 10 seconds after the launch's span (its start to 20 seconds after its end) runs `ps` once for all the looks due then, outside the run's lock and without any Apple event to Terminal, and takes the empty Terminal.app tabs that opened in that span -- a tty whose oldest process is a `login` started by Terminal.app, with only `login` and a shell on it -- leaving out the orchestrator's tab, the tabs the run's own sessions opened in (the tab script now logs the tty of the tab it takes as `new_tty`) and the stray tabs already counted. A launch whose look finds one is counted once in `terminal_stray_tabs` and in the new `terminal_late_stray_tabs`, and a warning names the tab's tty so it can be closed by hand; a look that cannot run `ps` says so on stderr. The tab script waits no longer; a poll or launch that makes looks returns later by the one `ps` run (tens of milliseconds, at most 2 seconds). The pending looks and the recent tabs' ttys are kept in the local run file (`terminal_stray_tab_checks`, `terminal_recent_tab_ttys`), cleared on a takeover or an adoption, and left out of the copy shared with other members. `ps` cannot tell which Terminal window a tab is in, so an empty tab you open yourself in any Terminal window during that span is counted too, as is another launch's tab whose session has ended by the look; docs/autopilot.md lists those and the cases the look misses (DFLT-00379).
